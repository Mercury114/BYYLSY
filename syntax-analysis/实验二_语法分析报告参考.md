# 实验二：语法分析阶段设计文档参考

> 本文对应“2026语法分析作业题目”，供整理实验报告时参考。程序验证结果为本地结果，不代表课程评测机的最终评分；心得部分应结合自己的实际过程修改。

## **一、实验内容**

本实验在词法分析程序的基础上实现 SysY 语言的语法分析。程序从 `testfile.txt` 读取源代码，由词法分析器识别关键字、标识符、常量、格式字符串和运算符，并保留每个单词的类别码、原始字符串、单词值和所在行号。随后，语法分析器按文法逐项识别编译单元、声明、函数、语句块、语句、表达式和条件表达式等成分。

本次作业要求使用递归子程序法，并将单词信息和指定语法成分写入 `output.txt`。语法成分标记按分析完成的顺序输出；`<BlockItem>`、`<Decl>` 和 `<BType>` 虽然需要识别，但不输出标记。分析时的前瞻只用于选择文法分支，不应提前输出单词。程序入口为 `Compiler.java` 中的 `main` 方法。

## **二、实验设计**

### 2.1 总体结构

程序由词法分析器、递归下降语法分析器和输出控制三部分组成。词法分析器一次扫描源文件并生成有序单词表，语法分析器通过当前位置索引读取单词。`main` 方法负责读取固定输入文件、调用两个分析阶段、处理错误接口，并将分析结果写入固定输出文件。

输出分为两类：消费单词时输出 `类别码 原始字符串`；完成需要展示的语法产生式后输出形如 `<Stmt>` 的标记。两类信息写入同一有序缓冲区，最后统一写入 `output.txt`，因此词法单词和语法标记保持语法分析时的先后关系。

### 2.2 数据结构与接口

| 数据结构 | 保存的信息 | 用途 |
| --- | --- | --- |
| `Token` | 类别码、原始字符串、单词值、行号 | 连接词法分析与语法分析；原始字符串用于输出，单词值和行号保留给后续阶段 |
| `LexicalError` | 错误代码、说明、行号 | 为词法错误处理预留统一接口 |
| `ParseError` | 错误代码、说明、行号 | 记录语法分析失败位置 |
| `Parser` | 单词表、当前位置、输出缓冲区、错误列表 | 执行递归下降分析并按序生成输出 |

`Lexer.scanAll()` 返回词法单词表，`Parser.parse()` 从编译单元开始分析。`expect()` 用于匹配必需类别码，`match()` 用于匹配可选或重复项，`check()` 和 `typeAt()` 用于前瞻。只有 `consume()` 会推进当前位置并写入词法输出；单纯的前瞻不会产生输出。

### 2.3 递归下降过程

语法分析为每个主要非终结符设置对应子程序，包括 `parseCompUnit()`、`parseDecl()`、`parseConstDecl()`、`parseVarDecl()`、`parseFuncDef()`、`parseBlock()`、`parseStmt()`、`parseExp()` 和 `parseCond()` 等。声明、定义、初值、函数形参及左值等规则也有对应的分析过程。规则中出现的可选项由条件判断处理，重复项由循环处理。

表达式文法原本包含左递归。为适配递归下降，程序将乘除模、加减、关系、相等、逻辑与和逻辑或规则中的左递归部分改写为循环，同时在每次完成相应产生式后追加语法标记。这样既避免递归下降中的无限递归，也保留了左结合的文法结构和输出顺序。运算层次由低到高依次为逻辑或、逻辑与、相等、关系、加减、乘除模、一元表达式和基本表达式。

语句分析通过当前类别码选择分支：复合语句、`if`、`while`、`break`、`continue`、`return`、`printf`、赋值语句、读入语句以及表达式语句。对于以标识符开头的语句，分析器在当前位置只做不消费单词的前瞻，判断分号前是否有顶层赋值符，从而区分赋值语句和表达式语句。

### 2.4 输出开关与错误接口

`compiler.syntaxOutput` 系统属性控制语法分析输出，默认值为 `true`，满足本次评测要求；设置为 `false` 时，程序仍执行分析并创建空的 `output.txt`，便于后续把分析功能复用于编译器内部而不输出调试信息。词法错误和语法错误均保留错误代码、说明和行号。当前作业只考核符合文法的程序，因此没有实现完整的错误恢复。

## **三、实验过程**

1. 阅读作业文法和输出样例，确认语法标记的命名、输出时机以及需要省略的 `<BlockItem>`、`<Decl>`、`<BType>`。
2. 将上次作业中的词法单词类别和扫描逻辑整合到本次 `Compiler.java`，保留原始词素、单词值和行号。
3. 按文法划分递归下降子程序；对左递归表达式规则采用循环实现，并检查每个表达式层次的结合顺序。
4. 将单词输出放在单词消费操作中，将非终结符标记放在对应产生式完成处，避免预读时输出单词或标记顺序错位。
5. 使用 Java 8 兼容目标编译，运行题目样例，并用上次文法解读作业的五个测试程序检查较完整的语法组合。
6. 将正式提交 ZIP 限定为 `src/Compiler.java`，把样例回归文件和报告参考保留在工作目录，不混入提交包。

本地编译命令如下：

```text
javac -encoding UTF-8 src/Compiler.java
java -cp src Compiler
```

运行目录中应放置 `testfile.txt`。输出默认写入同目录的 `output.txt`。调试时可设置 `compiler.syntaxOutput` 系统属性关闭语法输出。

## **四、实验结果与分析**

使用 `javac --release 8 -encoding UTF-8` 对源码进行编译，编译通过。题目给出的主程序样例输出共 46 行，与本地保存的预期结果逐行一致，覆盖了变量定义、读入、格式化输出、返回语句以及主函数和编译单元标记。

首次课程评测反馈为 28.20/30。查看评测对照后，发现所有列出的不一致项都发生在一元运算符之后：期望输出 `<UnaryOp>`，程序当时漏掉了该标记。现已在一元运算符被识别后输出 `<UnaryOp>`，并增加包含一元正号、负号和条件逻辑非的回归程序。修复后的本地检查通过；本次修改尚未再次提交课程评测，最终成绩以之后的评测结果为准。

随后运行上一项文法解读作业的五个测试程序。五个程序均成功完成分析；从本次输出中提取的词法单词行与上一题词法分析程序的输出逐行一致，说明语法分析的前瞻没有提前打印单词，单词消费过程也没有漏项或重复。五个程序的单词数量分别为 302、363、426、170、206。结合专门包含一元正号、负号和条件逻辑非的回归用例，文法要求输出的 29 种语法成分标记全部得到检查，且没有输出三种明确排除的标记。

| 检查项 | 本地结果 |
| --- | --- |
| Java 8 兼容目标编译 | 通过 |
| 题目样例输出 | 46 行逐行一致 |
| 上一作业五个程序 | 均完成分析 |
| 单词序列对比 | 五个程序均与词法分析输出一致 |
| 非终结符标记覆盖 | 29 种要求输出的标记均得到检查 |
| `<BlockItem>`、`<Decl>`、`<BType>` | 均未输出 |

上述验证说明样例中的输出顺序以及现有测试程序覆盖到的语法分支符合预期。它不能替代课程评测机对其他合法输入的检查，也不能据此推断最终成绩。若后续评测指出特定标记不一致，应优先根据产生式完成时机检查递归调用和标记位置。

## **五、实验心得体会**

本次实验让我进一步体会到，语法分析不仅需要判断输入是否符合文法，还需要准确记录分析过程。递归下降的子程序与文法规则一一对应后，代码结构较清楚；但表达式规则中的左递归不能直接照搬，需要转换为循环，同时保持原来的运算优先级和结合方向。

调试过程中，词法单词与语法标记的输出时机尤其容易出错。通过把单词输出集中在消费操作中，前瞻只读取类别码而不输出，能够避免预读单词被提前打印。对照题目样例和上次作业的程序逐项验证，也让我认识到测试既要检查程序是否能够运行，还要核对每一行输出的顺序和内容。

后续完善编译器时，可以继续沿用单词表、行号和错误对象等接口，在语法分析基础上逐步加入错误恢复、语义检查和中间代码生成。以上心得为参考草稿，正式报告应补充本人实际遇到的问题和处理过程。
